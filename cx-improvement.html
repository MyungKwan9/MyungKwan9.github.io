Priority 02장기 미해결과 긴급 장애 분리 관리

장기 미해결과 긴급 장애를 구분해 관리합니다.

데이터 근거
전체 표본에서 관련 문의를 계산하고 있습니다.
원인 가설
장기 미해결은 확인·이관 단계에서 지연되고, 긴급 장애는 즉시 영향 범위를 판단해야 할 가능성이 있습니다.
추가 확인
단계별 대기시간과 담당 이관 이력, 장애별 영향 사용자 수와 복구 시각이 필요합니다.
개선 제안
48시간 경과 알림과 담당 재확인 규칙을 두고, 긴급 장애는 별도 즉시 확인 큐로 관리합니다.
효과 확인 지표
48시간 이상 미해결 비율, 단계별 대기시간, 긴급 문의 최초 확인시간을 구분해 봅니다.

문의량만으로 원인을 확정하지 않았으며, 현재 표본에서 계산 가능한 현황과 실제 운영에서 추가로 확인할 지표를 구분했습니다.

현재 사용자 CSV 전체에서 환불 기준·환불 진행상태(이전 형식의 결제 취소 안내 포함), 장기 미해결, 계정·접근(계정·로그인 포함), 오류·장애의 긴급 문의를 집계합니다. 두 제안은 검토용 가설이며, 사용자 CSV의 원인이나 실제 개선 순위를 자동으로 판정하지 않습니다. 0건은 해당 조건의 티켓이 없다는 뜻입니다.

DATA & METHOD데이터와 지표를 어떻게 만들었나요?+

본 프로젝트는 가상의 고객문의 데이터를 활용해 CX 운영 데이터 구조화와 지표 설계, 문제 탐색 및 개선 가설 수립 과정을 시각화한 Portfolio 프로젝트입니다.

데이터 구조

한 행은 메시지 한 개가 아니라 문의 티켓 한 건입니다. 티켓 번호, 접수·최초응답·해결 시각, 채널, 유형, 상태, 우선순위, 원인 태그와 다음 조치를 담았습니다.

KPI 정의

접수 건수는 고유 티켓 수, 미해결은 미처리와 처리중의 합입니다. 장기 미처리는 분석 기준시각까지 48시간 이상 미해결인 건이며, 해결 소요시간 중앙값은 해결 티켓만 계산합니다.

분석 흐름

CSV 정리 → 필터 적용 → KPI 계산 → 차트와 처리 목록 갱신 → 반복·지연 패턴 확인 → 운영 개선 가설 수립 순서로 구성했습니다.

한계와 활용 범위

의도적으로 설계한 가상 패턴이며 실제 고객 행동이나 운영 성과를 뜻하지 않습니다. 48시간 기준은 이 프로젝트의 관리 기준이고 영업시간 SLA나 업계 표준이 아닙니다.

데이터 구조와 지표 기준, 화면 요구사항을 정의한 뒤 AI 지원을 활용해 구현과 검증을 진행했습니다. 실제 회사 데이터, 개인정보, 실시간 분석은 포함하지 않았습니다.

사용자 CSV: 컬럼명은 템플릿과 동일하게 유지합니다. 날짜는 YYYY-MM-DD HH:mm:ss 형식(Asia/Seoul)이며 ISO 형식도 지원합니다. 상태는 미처리·처리중·해결, 유형·우선순위·채널은 샘플과 동일한 분류를 사용합니다. 최초응답·해결 시각은 해당 이벤트가 없을 때만 비웁니다. 파일과 분석 기준시각은 페이지 메모리에서만 유지되며 새로고침하면 샘플로 돌아갑니다.
